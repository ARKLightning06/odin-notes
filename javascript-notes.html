Using JavaScript

To use JavaScript, use the script tag: <script> console.log("hello world") </script>

Console.log is like a print command basically, and you can see the console in inspect

Can also run scripts by linking a .js file: <script src="whatever.js"> </script>

Apparently you can also run scripts directly, like declaring a function then putting the function in a button's html, but this is bad practice

Generally, we run JavaScript through browser, though it's possible to do it otherwise also

Script loading strategies: for internal, place at bottom of body to ensure all html loads. For external, place in header with type="module" so it will allow html to load first. Other strategies too, but generally those will work

Comments also exist... pretty standard, // for individual, /* */ for group

Variables

Declare using let or const: let is changeable, const is constant... var also exists but who cares

Numbers exist, PEMDAS order of operations

Naming is important, make sure to name things well. camelCase is used, variable names can't start with digits, _ and $ are acceptable but - is not, certain words are reserved and can't be variables like let or return, and always name descriptively and consistently

Data Types

Apparently there are 8 data types

  1. Numbers: numbers... yeah
    • Includes floats and ints, specials like Infinity, -Infinity, and NaN.
    • All math is safe, even dividing by 0 etc, because at worse it returns NaN
    • NaN self propogates: any operation on NaN returns NaN, the only exception being NaN ** 0 = 1
  2. BigInt: exactly what it sounds like. A big int. Number goes up to +- 2^53 - 1, anything bigger append n to the end to make it BigInt (2423123123213123123213423412341234123412341234n for ex)
  3. Strings: words, declared with quotes, simple enough.
    • Apparently ' and " are the same, but ` (backtick) are special, called template literals - basically f-strings, allow you to embed JavaScript
    • Concatenation exists, with template literals can just womp em together but otherwise +
    • Use backslash \ to use quotes in strings or something similar
    • Use template literals to have multiple lines or \n for normal strings
    • Lots of handy dandy methods to make life easier, see references
  4. Booleans: True/False, boolean logic applies
    • Comparison operations: ==, !=, <, >, <=, >=
    • Strings: convert to unicode, so Z > A is true, though a > Z is also true because capitals come before lowercase
    • Can compare across data types: some conversions implicit, like '01' == 1, also true is 1 and false is 0
    • Use strict equality, or ===, for better comparisons: '' == false is true, but '' === false is false
    • Other wonky stuff with null and undefined, doesn't really matter but doesn't hurt to check it out
  5. null: nothing. Or maybe empty? idk, think empty set, it is nothing but nothing is something, sometimes
  6. undefined: empty. Different from null, kinda. Null is generally assigned to something empty, while undefined is reserved for a variable with nothing assigned to it
  7. Symbol: unique identifiers for objects
  8. Object: more complex data type

There's also the typeof operator - notice operator, not method, which returns the type of piece of data. The exception is null, which is returned as Object, even though it is not an object it's its own type

Functions!

Functions exist! Take parameters, then are called with arguments

Declared with function word, use return to return value

Variable scope basics, local variables are only accessible in the function while outer variables are accessible and changeable from within the functions... global variables are bad avoid using them

Default values: when being declared, use = to set a default value for a parameter

Like variables, name functions well

Anonymous functions: like lambda I think, basically instead of naming a function can leave it nameless, or anonymous, either with no name or with => sign

function (item) {return item * 2} //or item => item * 2

Callbacks: name for functions entered as parameters

Call stack: LIFO stack of function calls, basically last in first out, order of how function calls are evaluated, stack overflow is an error when it exceeds maximum depth

Errors

A few (three) types of errors:

  1. Syntax error: bug in the 'grammer' or syntax of the code
  2. Type error: bug in the data type of a variable
  3. Reference error: bug when attempting to reference an undefined variable

Errors are super helpful for debugging code

Debugger can be helpful for finding and fixing errors

Clean Code

Descriptive, consistent, readable

Use camelCase for naming variables and functions generally, though not always

Loops and Arrays

Loops do stuff iteratively... for loop, for ... of ... loop, while loop, do while loop

break: exit loop, continue: go to next iteration of the loop

Can label our loops: loopName: for..., then use that to break out of an outer loop from an inner or something similar

Arrays: order list of data, declared with []

Some array methods:

  • a.pop() extracts last element of array, or at some index, and returns it
  • a.push(item) adds item to end of array
  • a.shift() extracts the first element of array and returns it
  • a.unshift(item) adds item to beginning of array

a.length is a cool property, returns 1 + highest index, and since js arrays are weird this could actually be different from the 'length' of the array... also can be used to truncate (so a.length = 0 will clear an array)

Arrays are objects, so aliasing applies

Plenty of other array methods to explore

DOM Manipulation

DOM: Document Object Model

  • Tree of 'nodes' with parent child relationships... i.e. p, div, span etc with classes and ids
  • Use selectors to find nodes based off ids and classes, then use methods like container.firstElementChild and child.previousElementSibling to use relationships to select
  • Use methods to access nodes: element.querySelector(selector) //and element.querySelectorAll(selectors)
  • Create elements with document.createElement("div")
  • This just creates elements in memory. To actually add it to the DOM, use parentNode.appendChild(childNode)
  • Can also insert in a specific place or remove nodes
  • Can directly modify inline properties of a node, but for css it's better to add id's and class tags then edit a styles.css file
  • Use getAttribute(), setAttribute(), and removeAttribute()
  • Classes are in a list called classList, which you can .add() to
  • Can directly modify .textContext

When modifying DOM with javascript, make sure the timing is right. Can't edit stuff before it exists, so put it in the header etc

Events: can have events to have dynammic stuff happen

Can directly modify, or use addEventListener

Events include stuff like click, keys down, mouse etc

Can also pass callback functions into event listeners, and use parameter e to pass in event itself

Lots of other events to explore

Also plenty of other ways to manipulate events: preventDefault() will stop a default behaviour, like clicking on a link, and stopPropagation() will stop any subsequent events activated (for example, let's say you have an event attached to body and to a div under body, the div event will happen first, then the body, uunless you include stopPropagation() then only the div will happen)

Also note that it's better to handle events with as few events as possible, making one click event and differentiating based off id instead of making one event for each button you want, for ex

Also you can create an event then activate it with dispatchEvent()

Also you can create custom events with the CustomEvent() constructor, which takes eventType string and details, which can basically store data
